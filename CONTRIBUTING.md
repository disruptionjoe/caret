# Contributing to ACON

ACON is an open project. Contributions are welcome — new terms, refined definitions, better examples, notation improvements, and architecture patterns.

## How to Contribute

### Propose a new glossary term
1. Open an issue with the title: `[Glossary] Term Name`
2. Include: the term, a plain-language definition, and an example of when/why it matters
3. Keep it practical — if you can't explain when someone would encounter this, it probably doesn't belong yet

### Refine an existing definition
1. Open a PR with your suggested change
2. Explain why the current definition is unclear or incomplete
3. Provide a real-world example that illustrates the improvement

### Add a notation symbol or pattern
1. Open an issue with the title: `[Notation] Symbol/Pattern Name`
2. Include: what it represents, why existing symbols don't cover it, and a sketch of how it might look
3. Patterns should include a "what this shows" explanation

### Share an architecture pattern
1. Open a PR adding your pattern to the patterns directory
2. Include: an ACON diagram, a plain-language explanation, and when this pattern is useful vs. when it's not

## Principles

- **Practical over theoretical** — every term and symbol should connect to something people actually encounter when building agent systems
- **Plain language** — definitions should be understandable by someone who is new to agent systems, not just ML engineers
- **Specificity** — vague terms that could mean anything don't help. Each entry should have a clear, bounded meaning
- **No jargon for jargon's sake** — if an existing word works fine, don't invent a new one

## Code of Conduct

Be constructive, be respectful, be practical. This is a collaborative project aimed at making agent systems more understandable. Contributions from all backgrounds and experience levels are welcome.
